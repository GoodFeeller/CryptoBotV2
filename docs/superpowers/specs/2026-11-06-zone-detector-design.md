# Детектор зон: дизайн

Дата: 2026-11-06. Основание: видео «Практика торговли уровней и ATR» (Артём Звёздин) и модули `levels`, `ema`, `waves`, `structure`.

## Цель

Заменить заглушку `EveryNCandlesDetector` настоящим детектором. Он замечает момент, когда цена пришла в область ценности в конце исчерпанной волны, собирает в этой точке картину рынка и отдаёт её Claude. Решение о входе, сторона, стоп и тейк по-прежнему за Claude.

Успех этапа: команда `npm run situations` показывает на истории места, которые пользователь признаёт местами для поиска входа, а число ситуаций в месяц позволяет гонять бэктест через сессии Claude Code.

## Что решили

| Вопрос | Решение |
|---|---|
| Когда звать Claude | цена в зоне И волна исчерпана |
| Какая волна | текущая мелкая ИЛИ крупная волна на 1h прошла не меньше 90% обычного размера |
| Паттерн отвержения | ищет Claude по свечам 5m, код паттерны не распознаёт |
| Свечи для Claude | 72 × 5m, 200 × 1h, 100 × 4h |
| Архитектура | детектор в `signals`, модули анализа через интерфейс `MarketAnalysis` в `core` |

## Архитектура

```text
движок ──await detect──► ZoneDetector (signals) ──ситуация──► обезличивание + промпт v2 ──► Claude
                              │            │
                    MarketData (core)   MarketAnalysis (core)
                                               ▲
                              app/compose: levels, ema, waves, structure
```

- **Новое:** `ZoneDetector`, интерфейс `MarketAnalysis`, промпт v2, команда `npm run situations`.
- **Изменено:** `SignalDetector.detect` становится асинхронным; `Situation` получает картину рынка вместо `levels` и `indicators`; обезличивание; `app/compose`; конфиг; график получает метки.
- **Без изменений:** модули `levels`, `ema`, `waves`, `structure`, `MarketData`, брокер, риск.

### Изменения в core

Типы результатов переезжают из модулей в `core/types.ts`: `EmaReading`, `EmaStack`, `EmaSnapshot`, `Wave`, `WavePoint`, `WaveSnapshot`, `Trend`, `StructurePoint`, `StructureSnapshot`. Модули импортируют их из `core` и по-прежнему не знают друг о друге.

```ts
export interface MarketAnalysis {
  /** Основные уровни по дневкам и локальные по часовикам, совпадающие локальные убраны. */
  levels(daily: Candle[], hourly: Candle[]): Level[]
  ema(candles: Candle[], at: number): EmaSnapshot
  waves(candles: Candle[], at: number, scale: 'small' | 'big'): WaveSnapshot
  structure(candles: Candle[], at: number): StructureSnapshot
}

export interface SignalDetector {
  readonly isPlaceholder: boolean
  detect(ctx: SignalContext): Promise<Situation | null>
}
```

Настройки модулей (пороги разворота, периоды) задаёт `app/compose` при создании `MarketAnalysis`, детектор о них не знает. `levels` использует только последние 365 дневок и 720 часовиков, как в `npm run levels`: на них уровни и подбирались. Остальную историю детектор грузит ради EMA 200 на дневке.

### Ситуация

```ts
export interface Situation {
  symbol: string
  kind: string
  at: number
  /** Картина рынка в момент ситуации. У заглушек null. Цены реальные, шкалу для Claude строит обезличивание. */
  picture: MarketPicture | null
}

export interface MarketPicture {
  zone: { price: number; low: number; high: number; reasons: ZoneReason[] }
  /** Уровни в пределах nearbyLevelsAtr дневных ATR от цены, любого статуса. */
  levels: { price: number; class: LevelClass; status: Level['status']; bounces: number; falseBreaks: number; flips: number }[]
  waves: Record<'small' | 'big', {
    averageAtr: Record<'up' | 'down', number>
    current: { direction: 'up' | 'down'; startPrice: number; lengthAtr: number; share: number }
    lastWave: { direction: 'up' | 'down'; top: number; middle: number; bottom: number }
  }>
  structure: { trend: Trend; previousTrend: 'up' | 'down' | null; beyond: 'above_high' | 'below_low' | null; highs: StructurePoint[]; lows: StructurePoint[] }
  ema: Partial<Record<Timeframe, { stack: EmaStack; emas: EmaReading[] }>>
  /** ATR в процентах от цены. */
  atrPct: Partial<Record<Timeframe, number>>
}

export type ZoneReason =
  | { type: 'level'; class: LevelClass; bounces: number; flips: number }
  | { type: 'wave'; part: 'top' | 'middle' | 'bottom' }
```

`kind` у детектора всегда `'zone'`: без тикера и дат.

## Правила детектора

Детектор вызывается движком на закрытии часовой свечи по каждой монете, как сейчас.

1. **Данные.** Через `MarketData` загружает 600 свечей 1d и 720 свечей 1h, закрытых к `now`. Через `MarketAnalysis` получает уровни, EMA на 1h и 1d, мелкие и крупные волны на 1h, структуру 1h. Если какой-то модуль ответил «мало данных», ситуации нет.
2. **Кандидаты в зоны.** Активные уровни (`status: 'active'`, основные и локальные) и верх, середина и низ последней крупной волны на 1h.
3. **Зона.** Цена кандидата ± `zoneAtr` × ATR(1h). Пересекающиеся зоны склеиваются в одну: границы объединяются, цена зоны — середина, причины собираются вместе.
4. **Касание.** Диапазон последней часовой свечи пересекает зону: `low ≤ zone.high` и `high ≥ zone.low`.
5. **Исчерпание.** Хотя бы одна из волн (мелкая или крупная) отвечает «ок», её `current.share ≥ exhaustedShare`, и зона лежит во внешней половине этой волны: для волны вверх `zone.price ≥ start + length / 2`, для волны вниз `zone.price ≤ start − length / 2`.
6. **Выбор.** Если подходят несколько зон, берётся ближайшая к крайней цене текущей волны.
7. **Повторы.** Детектор помнит по монете последнюю зону и число вопросов. Если та же зона (цены пересекаются) была и в прошлый час, счётчик растёт; после `maxAsksPerVisit` вопросов ситуация по этой зоне не возвращается. Час без касания сбрасывает счётчик. Состояние живёт в памяти одного прогона; бэктест всегда идёт с начала, поэтому прогон воспроизводим.

Настройки в конфиге, секция `signals.zone`: `zoneAtr` 0.5, `exhaustedShare` 0.9, `maxAsksPerVisit` 3, `nearbyLevelsAtr` 3, `history` `{ "1d": 600, "1h": 720 }`.

Чего нет на этом этапе: фильтра кульминации, фильтра по структуре, распознавания паттернов в коде.

## Claude

- **Окна свечей:** в `claude.windows` добавляется `"5m": 72`.
- **Обезличивание:** все цены картины (зона, уровни, верх, середина и низ волн, старт текущей волны, максимумы и минимумы структуры, значения EMA) переводятся в шкалу «текущая цена = 100». Время точек структуры заменяется на «свечей назад». Тикера и дат нет.
- **Промпт v2:** новый файл `prompts/v2.ts`, v1 остаётся для старых ответов в кеше. `claude.promptVersion` становится `v2`. Содержание:
  - торгуем от зоны в конце исчерпанной волны;
  - вход только если на 5m видно отвержение цены: двойная вершина или дно, голова и плечи, флэт, свечи с длинными тенями. Если паттерна ещё нет, `enter=false`, через час спросим снова;
  - по структуре 1h обычная сумма сделки, против структуры меньшая;
  - стоп за паттерном плюс примерно ATR 5m; тейк до ближайшей противоположной зоны или на обычный размер волны в обратную сторону;
  - не входить, если прибыль меньше 1.5 риска или идёт кульминация;
  - вход только лимитным post-only ордером: для шорта чуть выше текущей цены, для лонга чуть ниже;
  - в разборе открытой сделки: закрыть раньше, если в зоне появился сигнал против позиции.

Новая версия промпта — это новая стратегия: старые результаты к ней не относятся.

## Команда `npm run situations`

```bash
npm run situations -- BTCUSDT,ETHUSDT 2026-10-01 2026-11-01
```

Проходит период час за часом с тем же детектором и тем же `MarketData` с ограничением по времени, что и бэктест, но Claude не зовёт. Выводит:

- список ситуаций: время, цена зоны и причины, какая волна исчерпана и на сколько процентов, структура;
- число ситуаций по монетам за период;
- картинки `data/situations/<монета>.png`: часовой график периода с зонами ситуаций и метками в местах срабатывания.

Для меток в модуль графиков добавляется `marks: { time, price, label }[]`.

## Тесты

- `tests/features/signals/zone-detector.test.ts` с поддельным `MarketAnalysis` и `MarketData`:
  - касание без исчерпанной волны не даёт ситуации, с исчерпанной даёт;
  - зона во внутренней половине волны не срабатывает;
  - проторгованные и пробитые уровни не зоны, но попадают в картину;
  - наложенные зоны склеиваются, причины объединяются;
  - повторы: не больше 3 вопросов подряд, сброс после часа без касания;
  - ответ «мало данных» от модуля не даёт ситуации.
- `tests/features/claude/anonymize.test.ts`: все цены картины в шкале; в теле запроса нет ни одного числа, равного реальной цене.
- Тесты движка и заглушек проходят с асинхронным `detect`.
- Тест метки на графике.

## Риски

- **Число ситуаций.** Если их окажется сотни в месяц на монету, сессии Claude Code не справятся. Поэтому сначала `npm run situations` и настройка порогов, потом бэктест.
- **Паттерн складывается после закрытия часа.** Смягчено повтором вопроса раз в час до 3 раз.
- **Лимитный вход.** Автор входит по рынку сразу после паттерна. У нас post-only лимит: при резком уходе цены сделка не откроется.
