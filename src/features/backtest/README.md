# backtest

Симулятор биржи и отчёт о прогоне.

## Что внутри

| Файл | Содержимое |
|---|---|
| `simulated-broker.ts` | реализация `Broker`, используется и в бэктесте, и в `live` |
| `report.ts` | отчёт: месяцы, просадка, сделки, ордера, издержки |
| `verdict.ts` | критерий цели: PASS, FAIL или N/A |
| `missed-entries.ts` | что было бы при входе рынком вместо неисполненного лимитного ордера |
| `run-writer.ts` | файлы прогона и журнал проверок |

## Правила симулятора

| Что | Правило |
|---|---|
| Выставление ордера | рассматривается со следующей свечи; если исполнился бы сразу, post-only его отклоняет |
| Вход | по цене ордера, комиссия maker, только если цена прошла ордер на `limitFillThroughPct` |
| Вход и стоп в одной свече | вход исполнился, стоп сработал |
| Вход и тейк в одной свече | вход исполнился, тейк в этой свече не засчитывается |
| Стоп и тейк в одной свече | сработал стоп |
| Стоп | по цене стопа или открытия, если оно хуже, плюс проскальзывание, комиссия taker |
| Тейк | по цене тейка, комиссия maker; гэп в нашу сторону не улучшает цену |
| Закрытие решением Claude | открытие следующей свечи плюс проскальзывание, комиссия taker |
| Фандинг | от объёма позиции по исторической ставке: лонг платит положительную |

Спорные случаи решены против нас, потому что порядок цен внутри свечи неизвестен. Ликвидация отдельно не моделируется: вход с ликвидацией ближе стопа отклоняет код.

## Вердикт

`PASS` только если всё верно: режим `validation`, детектор не заглушка, минимум 6 полных месяцев, издержки включены, медиана месяца от +60%, просадка до 50%. Прогон с остановкой или заглушкой получает `N/A`.

## Файлы прогона

`data/runs/<режим>-<советник>-<время>/`: `report.json`, `trades.csv`, `equity.csv`, `config.json`. Проверки `validation` дописываются в `data/runs/validation-log.csv`, чтобы было видно, сколько раз проверялся один отрезок.

## От чего зависит

Только от `core`.

## Как тестируется

`tests/features/backtest/`, сквозные прогоны в `tests/app/run-backtest.test.ts`.
