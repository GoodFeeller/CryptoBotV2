# claude

Решения Claude по входу и ведению сделки. Реализует интерфейс `TradeAdvisor` из `core`.

## Как устроено

```text
DecisionAdvisor  обезличивает запрос, разбирает ответ, возвращает реальные цены
   └ DecisionSource  откуда берётся ответ
        ├ SessionDecisionSource  файлы для сессий Claude Code, бэктест
        └ ApiDecisionSource      платный API, live и сверка
```

| Файл | Содержимое |
|---|---|
| `decision-advisor.ts` | советник и интерфейс источника |
| `anonymize.ts` | запрос без тикера и дат, цены свечей и картины рынка в шкале «текущая = 100», точки структуры как «свечей назад» |
| `schemas.ts` | схемы ответа |
| `prompts/` | версии системного промпта: v1 — черновик конвейера, v2 — торговля от зон по видео (текущая) |
| `session-source.ts` | обмен файлами с сессиями |
| `api-source.ts`, `anthropic-call.ts` | API, кеш, лимит расходов; SDK только во втором файле |
| `response-cache.ts` | кеш ответов API и расчёт стоимости |
| `random-side-advisor.ts` | случайная сторона, база для сравнения и бесплатного прогона |
| `estimating-advisor.ts` | оценка стоимости прогона через API |

## Бэктест через сессии

1. `npm run backtest -- ... --advisor session` доходит до запросов без ответа и останавливается со статусом `needs_decisions`.
2. Запросы лежат в `data/decisions/<версия промпта>/pending/<ключ>.json`: системный промпт, тело и схема ответа.
3. Сессия пишет ответы в `answers/<ключ>.json` с тем же именем файла.
4. Запустите ту же команду снова: готовые ответы подставятся, и прогон дойдёт до следующих запросов.

Сессия должна работать в отдельной папке без репозитория, `data/` и поиска в интернете. Иначе она сможет узнать будущее, и бэктест будет испорчен.

## Что проверяется

Здесь проверяется только форма ответа. Правила сделки (стороны цен, потеря, маржа, ликвидация) проверяет движок через `core/trade-rules.ts`.

## От чего зависит

От `core`, `zod` и `@anthropic-ai/sdk`.

## Как тестируется

`tests/features/claude/`, без сети. Настоящий запрос к API проверяется только вручную и за деньги.
