# levels

Поиск горизонтальных уровней. Правила и основания описаны в [спеке уровней](../../../docs/superpowers/specs/2026-10-31-levels-design.md). Сигналов здесь нет, а в логике бота уровни пока не участвуют.

## Что принимает и отдаёт

`findLevels(candles, options)` получает закрытые свечи и настройки, отдаёт уровни от сильных к слабым. Настройки: `MAJOR_LEVELS` для дневок и `LOCAL_LEVELS` для часовиков. Все пороги заданы в ATR.

`combineLevels(major, local, tolerance)` убирает локальные уровни, совпавшие с основными.

## Правила

- Кандидаты: подтверждённый разворот, излом тренда, проторговка, разворот на паранормальной свече.
- Близкие кандидаты склеиваются в один уровень.
- Отскок засчитывается, только когда цена ушла от уровня минимум на 1 ATR.
- Пробой уровень не отменяет: сторона меняется, а следующий отскок с другой стороны считается зеркальным.
- Сила растёт в основном от числа отскоков.
- Проторгованный уровень (`status: 'traded'`) нельзя использовать, пока цена не даст новый быстрый отскок от него.
- Уровень, который меняет сторону чаще, чем в половине отскоков, не показывается.

Функция видит только переданные свечи. `bornAt` показывает, когда уровень стал известен.

## Как посмотреть

```bash
npm run levels -- BTCUSDT,ETHUSDT
```

Картинки появятся в `data/levels/`. Без аргумента команда рисует все монеты из конфига.

## От чего зависит

Только от `core`.

## Как тестируется

`tests/features/levels/` на синтетических свечах. Качество уровней оценивается глазами на реальных графиках.
