# trading

Движок сделок: один и тот же в бэктесте и `live`. Знает только интерфейсы из `core`.

## Что принимает и отдаёт

`TradingEngine` принимает реализации `MarketData`, `SignalDetector`, `TradeAdvisor`, `RiskGate`, `Broker`, `Notifier`, `ChartRenderer` и настройки. Метод `step(now)` вызывается на закрытии каждой свечи исполнения. `stats()` отдаёт счётчики для отчёта.

## Порядок шага

1. События брокера: исполнения и закрытия уходят в Telegram.
2. Просадка: при первом срабатывании защиты отменяются ордера и уходит сообщение.
3. Разбор сделок, у которых с исполнения прошло кратное 60 минутам время.
4. Новые входы, только на закрытии сигнальной свечи и если защита не сработала.

## Правила входа

- Одна позиция или ордер на монету, в сумме не больше `maxPositions`.
- Claude вызывается, только если детектор нашёл ситуацию и запас потери больше нуля.
- Запас считается заново для каждой монеты, поэтому ордера этого же шага его уменьшают.
- Решение советника проверяет `core/trade-rules.ts`. Негодное решение не исполняется и уходит в Telegram как ошибка.

## Сбои

Сбой монеты пропускает её в этом шаге. Сбой Telegram или картинки не прерывает торговлю: без картинки сообщение уходит текстом.

## От чего зависит

Только от `core`.
