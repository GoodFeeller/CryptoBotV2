# core

Общий язык проекта: типы данных и интерфейсы, через которые модули общаются друг с другом. Логики торговли здесь нет.

## Что внутри

| Файл | Содержимое |
|---|---|
| `types.ts` | свечи, ситуации и картина рынка, снимки EMA, волн и структуры, решения Claude, ордера, позиции, сделки, события брокера |
| `ports.ts` | интерфейсы: `Clock`, `MarketData`, `MarketAnalysis`, `SignalDetector`, `TradeAdvisor`, `RiskGate`, `Broker`, `ChartRenderer`, `Notifier` |
| `timeframes.ts` | длины таймфреймов и проверка закрытия свечи |
| `atr.ts` | ATR по свечам: общий для уровней, EMA и волн |
| `pivots.ts` | развороты волн: общие для уровней и волн |
| `trade-rules.ts` | проверка решений советника, расчёт объёма и потери при стопе; применяется при любом советнике |
| `errors.ts` | `FatalRunError`: ошибка, после которой продолжать нельзя |

## Что принимает и отдаёт

Модуль ничего не запускает. Фичи реализуют интерфейсы из `ports.ts`, движок вызывает их, а `app` соединяет одно с другим.

## От чего зависит

Ни от чего: ни от других папок проекта, ни от внешних пакетов. Это проверяет `npm run check`.

## Соглашения

- Время всегда в мс UTC.
- `Candle.closeTime` это начало следующей свечи, а не последняя миллисекунда текущей.
- Цены реальные. Шкалу для Claude знает только фича `claude`.
- Бот описывает рынок через `Situation`. Сторону, цены, плечо и сумму выбирает Claude, код только проверяет их.
- Сумма сделки считается от `Equity.balance`, просадка от `Equity.total`.
- Размер 1R задаёт `Position.initialStop`, а не текущий стоп.
- `MarketData.candles` не возвращает незакрытые свечи. На этом держится защита от заглядывания в будущее.
- `Broker.close` не закрывает позицию сразу. Все исполнения приходят через `Broker.poll`.

## Как тестируется

В `tests/core/` проверены таймфреймы и правила сделки. У типов и интерфейсов нет поведения: их проверяет компилятор и тесты реализаций.
